# 本地运行及数据约定

## 配置

SQLite 中 `config_state` 维护递增配置版本，stocks/themes 使用稳定 ID，审计保存操作者、来源消息 ID 与前后版本。股票带市场代码；新增与恢复记录生效时间，关注点调整不重置 seen。名称只能匹配已配置目标或服务端明确维护的候选，模型生成的证券代码不能充当可信来源。

一次新闻轮次读取一次配置快照，检索和分析使用同一版本。主题有独立关键词与检索任务；关注点用于分析重点，不是强制排除其他重大新闻的筛选器。空名单合法，初始化不能复活用户删除的默认目标。

## 消息、任务和回执

回调先验签、解密并验证企业/应用及管理员身份。无 MsgId 的事件使用稳定散列去重。明确指令在短事务内处理；配置、审计、inbox 完成状态和 outbox 回执一起提交。回执收件人固定为发起人，不使用预警广播收件人。

自然语言保存读取时的快照和配置版本后交给 worker。模型调用期间不持有写事务，结构/字段/目标验证全部通过才原子应用；版本冲突要求用户重新检查。失败只产生回执，不修改配置。任务有租约，进程中断后可重新领取；配置应用和任务完成同事务，避免重复修改。

## 新闻与投递

旧全局模式保留原始目标首次基线和24小时发现窗口；新增/恢复目标从生效时间起纳入监控。schema4成员流程使用下述质量策略：每轮最多10个新逻辑分析任务，成功缓存可复用；24小时发现窗口不等于24小时实时推送窗口。文章池、成功分析缓存及成员评估通常保留15天，事件和成员提醒证据至少保留30天。

成员流程分别持久保存原始观察、规范报道、成功分析、失败尝试、成员评估、通知候选和outbox。网络请求前用短事务领取分析任务、预留预算，网络期间不持有写事务；网络后结算用量并复查租约、成员资格代次及配置版本，成功结果才可缓存和用于评估。成员评估及必要的通知候选在同一短事务提交，分析失败不标记已处理。投递失败依靠持久outbox重试；已被企业微信接受的分段逐段记录，重试从剩余分段开始。响应丢失或接受后落库前崩溃时可能重复，不能保证端到端严格一次；指数退避后进入dead的消息可经 `retry-outbox ID` 手动恢复。

### 报道、事件及内容筛选

规范报道优先使用来源命名空间和上游ID，并建立规范URL别名映射；只移除已知追踪参数，保留可能承载身份的业务参数。保留每次原始标题、摘要、链接及来源时间。查询高亮、空白、摘要截断或不同检索片段不单独成为实质修订；有证据的金额/指引更正、撤销、取消及实施进展等可产生新修订。来源时间刷新不延长旧事实寿命，只有明确实质更新证据才允许记录新的披露时间；first_seen不可覆盖。

事件层采用保守确切事实匹配：主体、事件类型、披露日与规范事实标题等相同才跨URL复用，未知事件保持报道范围；不以标题相似度合并不同经营事件。模型自由措辞不作为事件身份。相同事件不同目标或关注需求仍独立判断，同一成员的多目标结果合并提醒；后补关联目标不能重新发送已通知原文。

AI之前过滤高置信纯行情模板，包括南北向净买卖、融资融券日报、涨跌成交复盘、技术指标及普通目标价观点。有业绩、订单、产品商业化、产能、供需价格、监管、重大减持、回购或经营风险事实的混合材料继续分析；不能按“卖出”“下跌”等单词一概屏蔽。规则不确定则保留待判断；模型返回受约束重要性、方向、基本面判断、新事实及可选事实日期，不执行SQL、Shell、Python或模型提供的外部操作。

### 时效和提醒窗口

普通实时事件固定到期时间为可信披露时间加2小时。来源时间未知或冲突、未来超过5分钟时待核对，不能用抓取时间冒充披露时间。隔夜经营事实在09:00至09:15收集分析，于09:10至09:15前最多形成一次晨间摘要、最多3个独立事件；未及时完成或超容量不转为日内逐条补发。重大风险须有明确披露证据才可使用来源时间起24小时例外，不能仅靠模型判为“重大”突破时效。

普通重要事件按成员在半小时边界形成摘要，每30分钟最多一条、每条最多3个独立事件。超额候选保留排队资格，到期退出且不续期；重大事件可及时入队。每段发送前重新检查成员、订阅和候选固定到期时间，已接受分段保留检查点，到期停止剩余段。显式人工历史补查走独立确认入口，不因实时策略变更自动扩大补查范围。

### 分析任务、用量及检索

最多5个兼容任务组成一次DeepSeek请求，每项有唯一task_id及独立目标/关注配置；组织、私有成员域和重大预算资格分别分组。整份JSON损坏或task_id缺失、重复、未知时整批不能确认成功；身份完整时逐项校验，只恢复失败项，已持久成功项继续复用。每轮最多10个新逻辑任务，并另计真实请求和失败；同公共键同轮仅尝试一次。失败状态与成功缓存分开持久保存，失败后依次冷却5、15分钟，第三次及以后每次冷却60分钟；尚有时效的任务才恢复，提供方故障另有按组织/隐私域隔离的熔断。

新闻默认每小时60,000、北京时间自然日300,000 token预算，20%为疑似重大预留；`NEWS_HOURLY_TOKEN_BUDGET`、`NEWS_DAILY_TOKEN_BUDGET`、`NEWS_MAJOR_RESERVE_FRACTION`可配置，普通任务不能搭重大批次消费预留。网络前原子预留，网络后按供应商真实total_tokens结算；无usage的失败或超时保留未知实耗，用明确保守估算单列budget_charge。输入、输出、缓存命中/未命中及模型指纹只保存安全元数据，不保存原始模型正文或凭证；截断和结构校验失败取得的usage仍记录。worker启动会保守结算超时遗留预留。管理意图用量按intent分类独立记录，不混入新闻预算；token记录不等于供应商金额账单。

真实东方财富检索平时只查目标主词，整点及每小时:15/:30/:45补查全部别名或主题关键词；主词结果为空或失败即回退完整查询。主词非空不代表别名覆盖完整，也不取消15分钟补查。成员模式真实DeepSeek的dry-run仅读已有成功缓存，不新增模型调用；无缓存任务保持待处理，Fake模式仍可演练整个流程。离线合成回放验证规则与幂等，不证明真实模型召回率或已实现50% token节省。

调度固定北京时间工作日 09:00 至15:00每5分钟一次，不排除法定休市日。计划时间槽和全局监控租约防重；不补跑离线所有历史时间槽。`MONITOR_ENABLED` 只控制自动新闻调度，管理指令与回执仍可工作。不要在 Web worker 中启动调度器或额外设置宿主机 cron。

## SQLite 与备份

默认使用 rollback journal（DELETE）及短事务、busy timeout。开发环境 SQLite 为3.50.4；官方确认该版本仍受 WAL-reset bug影响，因此默认不启用WAL。未来启用WAL前必须核对实际容器SQLite包含修复（官方列出3.51.3及以后，或3.50.7/3.44.6回补版本），不能仅看Python版本。

`backup` 使用 SQLite online backup API 并做 integrity_check，目标必须不存在。恢复演练在独立路径执行；真实恢复需先停写，明确备份时点之后配置/任务丢失范围，不能随着代码回滚覆盖共享数据库。运行数据、环境文件与证书均不属于代码发布物。

## 组织内独立订阅（schema4）

旧全局模式保留兼容；成员准入不会自动启用独立订阅。显式指定唯一旧配置拥有者后，迁移完整配置、审计及已处理基线，再设置持久模式标志。迁移事务拒绝未完成旧通知/意图任务和仍存活的监控租约。schema4增加规范报道、事件/成员提醒证据、通知候选、持久尝试和模型用量表，保留旧配置、seen、评估及投递记录，并从已有历史补建去重证据；不清库、不重建全量首轮基线。升级后不能直接用低版本schema应用回退。常驻worker每轮重读模式，旧流程认领租约时也检查模式，防止切换竞态产生广播。

成员按已核验组织ID/UserID准入；普通成员和管理员在微信中都只操作本人订阅，成员准入/撤权使用可信本地运维入口。成员配置以完整领域行JSON持久化，在隔离内存SQLite中复用原ConfigStore校验及命令规则，再用成员版本和资格代次在共享库短事务保存；没有每成员数据库文件或独立调度器。新成员为空订阅，撤权后恢复只重新启用既有启用目标的生效时间，不补发停用期间旧闻。

回调、确认、上下文、审计、异步任务及回执均绑定成员。自然语言任务冻结本人的快照，模型调用前后均重新检查成员代次及配置版本；模型不得选择成员或收件人。队列有组织总量和每成员限额，已撤权任务不应用旧修改。

检索需求共享采集，规范报道及确切事件版本持久化。AI按事件/报道、目标及规范化关注需求划组，同文不同目标分别判断；公开需求在组织内复用，设置私有分析后使用成员独立缓存和失败恢复域。模型、提示词及输出结构版本参与缓存；收件人、阈值等通知设置不使分析缓存全量失效。关注点不排除目标的其他重大风险，推送按成员当前规则判断。

成员评估与全局文章池分开，同一成员同篇多项命中合并一条定向通知并分别展示各目标影响；评估与通知入队同事务。发送每段前检查成员和订阅资格，成员通知不回退到全局收件人，保留已有分段检查点与未知网络结果可能重复的限制。显式历史补查必须指定成员和唯一目标；首次生效、暂停/恢复、旧基线和正常配置变更保持不自动重发旧闻。
