# 新闻降噪、事件去重、时效与模型成本改进计划

日期：2026-10-23。状态：源码对比及生产只读取证后，操作者已要求“按计划修改”。以下保留分析与验收目标；当前代码已实现，正在完成全量回归与生产发布。实际命令、结果与未验证项见PROGRESS.md，不以合成样本代替线上成本验收。

实现边界：事件合并采用有证据的规范主体、类型、日期和确切事实指纹；相似但无法证明同一事件的报道保留独立，暂不使用宽松语义相似度合并。可信更正和历史摘要分别保存，摘录变化不会覆盖已确认更正。实际token缺失时估算值仅用于预算扣减，单独标记；节费50%仍是上线观察目标。新闻预算默认每小时60000、北京时间每天300000 token，普通任务最多使用80%，其余留给疑似重大任务；配置管理意图单列计量。真实DeepSeek的dry-run只预览已有缓存，不产生新付费请求。

摘要目前保留原4000字符上限及来源证据，先清理格式并按输入体积/剩余预算自适应拆批，单项超限明确待处理；没有增加付费压缩步骤。本次真实摘要最长仅154字符，压缩不是已证实的主要节费点，后续按usage评估有证据边界的进一步压缩。

## 为什么比旧服务更贵、更频繁

| 环节 | 旧服务保留源码 | 新成员服务当前实现 | 影响 |
| --- | --- | --- | --- |
| 检索 | 固定3家公司，各用公司名请求一次、第一页20条；别名仅本地核对 | 名称、别名、代码及主题词逐个请求；当前共16词 | 搜索覆盖更宽，重复摘要和非基本面候选也更多；不是每词都必然返回20条有效新闻 |
| AI请求 | 每轮最多10篇合为一次请求 | 每文章版本×目标/关注组分别请求，每轮最多10次真实请求 | 重复输入规则/结构/目标，多个相关目标及格式变体继续消耗调用；共享成功缓存已有实现，不能说按成员机械倍增 |
| 去重 | 同公司+URL稳定身份，不能识别不同URL的同事件 | 上游身份+原始标题/摘要/URL/媒体/时间形成版本；按成员/版本/目标去重 | 同ID同URL的检索呈现差异也可能重新分析、重复提醒；缺少事件层 |
| 时间 | 24小时、未来容忍1小时，最旧优先 | 同样窗口，持久文章池按发布时间升序，逐目标预算分轮消化 | 旧闻不是新引入的时间窗口，但扩大的池及处理方式让其在早盘持续出现；没有发送到期检查 |
| 提醒 | 一轮全部重大/重要拼成一条消息，必要时分段 | 每成员每文章版本单独通知，同版本多目标才合并 | 即使有效事件数相同，手机提醒次数也会变多 |
| 内容偏好 | 要求解释利润/估值机制，没有明确行情硬过滤 | 仍主要依赖模型重要性和方向判断，缺少基本面事实闸门 | 净买卖、涨跌回顾被判重要后即可投递；只改关注点不能阻止 |

同样有10轮且均有新候选时，旧实现最多10次批量请求，新版该窗口实际100次；不能据此宣称token或账单正好增加10倍。两版传输代码都没有持久记录usage，旧实际触发器频率也未保存在legacy代码中；旧线上运行频次、账单、缓存计费与实际模型消耗没有本轮证据，不能编造倍数。新单次max_tokens1200与旧整批3200也是上限，不是实耗。

## 第一阶段：先消除已证实的重复和无效分析

### 1. 文章身份稳定，格式变化不代表新事实

- 保留原始观察记录，新增规范文章身份，优先来源命名空间+上游ID，并建立规范URL别名映射。过滤已知追踪参数及片段，不删除可能承载文章身份的业务参数。
- 清理查询高亮产生的空格、HTML实体、全半角和无意义格式变化；不能把不同原文的真实数字、主体或日期一并抹去。摘要是检索片段，不再独自决定“实质修订”。同链接同ID不同查询摘录先归同一报道，合并关联目标与出处。
- 版本更新区分“观察信息更完整”和“事实发生实质变化”。发布时间刷新、媒体名/链接改写或摘要截断不自动重分析/重发；财报更正、金额/比例/指引变化、订单撤销、计划变实施等有证据的变更才重新评估，通知注明新增事实。
- 同报道跨股票/主题目标仍分别分析影响，但向同成员合并通知。后续补关联目标不能单独再发原文：未发送且无已接受分段时可补齐；已发后只更新关联，除非确有值得通知的实质进展。

### 2. 规则预筛在AI之前执行

- 高置信纯行情模板默认不调用新闻模型、不发实时通知：南北向/港股通每日净买卖、融资余额/融券日报、涨跌幅/成交额/换手播报、无新经营事实的交易复盘、技术指标和普通目标价推荐。
- 有新经营或行业基本面事实的混合文章继续分析：业绩/指引、收入/利润/毛利、订单/客户、产品商业化、产能/良率、供需与产品价格、资本开支/融资偿债、并购、监管、诉讼、经营调整。
- “卖出”“下跌”不作单词黑名单；控股股东/高管重大减持、控制权变化、公司回购，以及被股价标题包装的业绩暴雷/经营事故必须保留。重大行业政策、上下游价格或需求变化也不以未直接提到公司名而一律排除。
- 规则不能确定时保留为待判断，要求模型提取受约束的事件类别、实际新事实、事实日期、证据和对目标经营的影响；程序执行去重、时效及通知决策，不让“被评为重要”绕过基本面/时效政策。
- 过滤记录带原因和规则版本，供离线抽查。模型失败、网络异常、预算不足不可写成“普通/已完成”或永久负缓存。

### 3. 稳定请求和失败预算

- 同公共分析键同轮只发一次请求，包括失败；失败状态独立于成功分析缓存。普通任务建议首次加2次自动重试，共3次，失败后分别退避5分钟、15分钟；达到上限进入可查的待恢复状态，不伪装成无价值或已完成。达到来源固定有效期的普通任务停止；尚有时效者可在60分钟冷却后、受独立恢复预算约束重新尝试，不因重启重置次数。
- 疑似重大任务使用单独预留预算，失败/熔断和持续预算不足须可见告警、保留冷却后的恢复资格，不能因普通任务3次上限永久失去处理机会。普通及重大任务的小时/日总成本仍受统一预算约束，不能借“重大例外”无限付费重试。
- 超时可能已收费，按尝试计入预算；内容或关注需求实质变化可生成新任务，普通重启不重置次数。提供方异常时熔断并在恢复后按公平顺序处理，重大预留与普通预算分开。
- 失败冷却不能跨组织/私有成员串用；撤权、资格代次、版本校验及已成功目标结果的缓存继续保留。

## 第二阶段：实时、隔夜与提醒频率分开

以下默认值已进入实现，发布前通过离线回放，生产效果需自然运行验收。晨报具体投递窗口为09:10至09:15之前。

| 项目 | 建议默认策略 |
| --- | --- |
| 抓取 | 保留24小时发现/核对窗口及历史存档，唯一worker仍每5分钟扫描 |
| 实时普通重要事件 | 仅最新2小时内新披露、仍有经营意义的事实进入实时候选；过期历史回顾不耗实时模型预算 |
| 隔夜 | 09:00开始收集并分析昨晚新披露的重大/重要经营事实，最晚09:15发一次晨间摘要，最多3个代表事件；没有已完成且合规事件不发，不承诺09:00即完成模型分析。普通行情不入晨报，日内不逐条补发；超容量事件保持可查，重大风险不受普通摘要容量限制 |
| 重大突发/新进展 | 去重后及时通知；重大性不代表无条件突破时效，须有新披露/实质更新证据，保留来源时间及事实时间。必要的24小时例外明确标注隔夜/补充，不能把老文改时间当突发 |
| 常规重要提醒 | 按成员每30分钟最多1条合并摘要，每条最多3个独立事件；其余有效候选公平排队，到期退出，不延长有效期或无限跨日补发 |
| 发送到期 | 入队固定expires_at，发送每段前复验；重试不能重新计算到期。已发分段保持检查点，到期后停止剩余段并保留审计 |
| 消息内容 | 显示首次披露/发布时间、事实所属日期、新事实和经营影响；同一报道多个目标分别说明但只提醒一次，压缩冗长的泛化影响分析 |

新增不可覆盖的first_seen_at及last_seen_at，保留原始source_published_at、可选event_at和信息新披露时间。首次抓到旧文不等于新新闻；先更新first_seen也不能绕过来源时间。来源/事实日期未知或冲突时进入待判断，不直接视为旧闻丢弃；未来超过5分钟的异常时间先隔离核对，不能仅因刷新页面时间变成新披露。普通到期时间固定取可信披露时间+2小时，晨报固定截止09:15，重大例外单独记录证据和有效期。顺序改为疑似重大新事实→新经营事实→其他待判断，辅以成员公平及最久等待配额，停止一味从最旧新闻开始消耗预算。

查询也分层：未验证覆盖率前保留既有检索；回放通过后，每目标优先主检索词，其余别名固定周期轮查、失败/低覆盖补查，建议15分钟至少覆盖一次别名组。主词非空不等于覆盖完整，必须验证仅别名命中的重大事件仍可及时发现。主题查询保留但独立限额，要求明确行业经营关联，不以扩大命中量作为质量目标。

人工历史补查仍通过显式成员/目标/时间窗和原有确认入口，不因实时策略改变而偷偷全量补发。管理指令回执不计入新闻摘要频率。

## 第三阶段：事件层与小批量分析降低长期成本

### 事件层

在文章之外增加事件与成员提醒账本；使用规范主体、事件类型、发生日/报告期、公告编号及关键事实建立事件。默认至少保留30天事件指纹和已通知证据；周期性数据按交易日/报告期区分，不能把不同日同类事件永久合并。

同事件不同媒体/转载只选择一个证据更充分的代表；新增媒体或改标题不提醒。金额/数量/指引/进度/结论/风险实质变化允许一次进展提醒，并展示变化。相似标题只是候选分组，不凭相似度把同公司同日财报与减持等不同事件合并。公司跨市场的相关目标可在同成员提醒中并列分析，不能共用一个总利好/利空。

### 小批量AI及用量

- 在本地预筛、规范文章、事件去重及缓存之后，按兼容组织/隐私域把最多5个独立任务合成小批请求；每项有唯一task_id、单目标/关注配置及独立结果，继续逐项校验、缓存与失败恢复。私有背景不得混入其他人的请求，不同目标不能被折成一条总判断。
- 保留“最多10个实际逻辑任务/轮”的公平约束，并另计真实HTTP请求/重试；小批必须同时限制输入和输出大小，避免截断。整体JSON可解析、task_id唯一完整时才逐项确认成功并持久化，单项失败只恢复该项；整份JSON损坏或身份歧义时不能猜哪些项成功，按未完成处理，已独立验证并持久化的结果继续复用。
- 摘要先做有证据边界的压缩，保留主体、时间、关键金额/经营数据和风险，不靠盲目截短换成本。结果建议影响依据≤180字、待核实≤80字；批量上限按项数设置并通过截断测试，不能把单条1200上限机械用于整批。
- 先记录再定量调预算：新闻与管理意图分别统计请求、逻辑任务、命中缓存、跳过、失败及输入/输出token；有返回时保存prompt_tokens、completion_tokens、cache-hit/cache-miss和模型指纹，不存原始模型正文。失败/截断已经取得的usage也计入，缺失则标未知，不以字符数或请求数冒充实耗。
- 固定规则前缀以便供应商缓存复用，但供应商缓存与本地结果缓存分开观测，不承诺必然命中或固定节省。每日/小时token预算、普通任务限额及重大预留依据实测设置，耗尽可见、可恢复，不靠静默漏报控制费用。

DeepSeek接口明确返回上述用量字段：[Chat Completions](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)；上下文缓存属于尽力而为，并不等于跳过输出计算：[上下文缓存说明](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)。批量减少请求次数，不保证token或费用按相同比例下降。

## 验收与发布顺序

1. 先实现文章规范去重、高置信噪音预筛、失败冷却、来源/首次发现时间及token观测；再加入发送到期、实时/隔夜与按成员摘要；最后在这些闸门后引入事件层和小批量分析。事件层成熟前，不能把文章层修复宣传成已经覆盖跨来源同事件。
2. 用同一批脱敏/合成材料、成员配置和虚拟时钟离线回放旧新决策：至少150条，含≥30条重要基本面/重大/实质更新、≥30条重复/旧闻、≥30条纯行情，并补相近标题不同事件与混合内容。生产完整敏感消息不进入fixture或Git。
3. 明确回归：本次两组同ID/URL的格式变体在同分析需求下零重复模型调用、同成员仅一次通知；不同目标各允许一次独立分析，各目标/关注点影响正确，不能为了省token错用其他公司的结果；同一事件转载仅一次；金额更正仍提醒；南向净卖出不推而控股股东重大减持保留；20条隔夜回顾不挤占1条新订单；重试到期/撤权/半段成功/重启不重发已接受分段。
4. 离线决策验收要求：标注重大及实质更新用例全部保留；重要基本面召回目标≥95%；本次已知纯行情模板零实时推送、零新闻模型调用；确定重复回放零重复提醒。更广泛同事件重复率目标≤5%，同材料新闻分析任务/token降低目标≥50%，均为待验证目标，不是本轮已达收益。
5. 机械预筛/幂等可用离线fixture验证；真实模型批量质量与实耗节省需随后受控、固定样本对照，不用FakeAnalyzer结果宣称模型召回或真实token节省。无需为本轮分析额外付费调用。
6. 迁移按递增schema与策略版本执行，保留原文章、个人配置、seen、成员评估及已发送outbox。用已有已发记录补建规范身份/事件提醒证据；不清库、不重新建全量首轮基线、不因新提示词批量回放旧通知。未发送且按新政策过期/纯行情的候选可取消并写明原因；成员评估与入队仍短事务，远程请求期间不持有写锁。
7. 完整离线测试、版本化备份和现有CI/受限发布链路通过后再上线，观察自然轮次的每100候选token、过滤率、合并率、重复/过期拦截、积压年龄与真实提醒数。业务监控开关和实际收件范围沿用原授权，历史补查、试发消息及新增来源不混入此改动。
