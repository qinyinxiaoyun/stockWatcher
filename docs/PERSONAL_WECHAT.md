# 个人微信接收与管理

## 已接通的方式

2026-10-22已在当前唯一成员账号真实验收：个人微信关注组织的微信插件后，可收到“股票新闻助手”的定向应用消息，也可在个人微信应用会话发送“查看监控”并收到本人订阅回复。

通知后端仍是现有企业微信自建应用和成员UserID，不是普通好友/微信群群发，也没有另装ClawBot或第三方转发平台。手机端入口改变不需要为同一成员再建一个订阅、收件人或重复投递通道；一条应用消息可能同时出现在企业微信和个人微信。

现有独立订阅、成员权限、推送等级和发送前资格复核继续生效。个人微信扫码关注不自动授予全局管理权限；回复仍只操作、展示本人配置。服务端不能仅凭发送API成功判断哪个客户端显示了消息，客户端收件与双向操作必须由本人确认。

## 当前成员使用

在个人微信中打开已关注组织的“股票新闻助手”，接收后续符合本人订阅条件的预警；查询时发送 `查看监控`，查看命令发送 `帮助`。现有股票/方向/关注点等命令走同一成员权限校验，并非开放了新的越权入口。

本次未修改订阅，验收前后个人配置版本均为2，配置指纹一致。自动监控保持已授权开启状态，代码及镜像仍为0c988da…；不需要为绑定插件重启服务或重新部署。未改变名单、凭证、应用可见范围或收件人。

## 后续成员接入

后续新增成员仍须明确授权并先完成组织准入、应用可见范围、服务端成员登记和个人订阅设置；扫码本身不完成这些步骤，新成员默认空订阅。不要沿用本次单条测试授权给其他人发消息。

| 页面/位置 | 操作 | 应看到的结果 |
| --- | --- | --- |
| 企业微信管理后台 → 通讯录 | 成员本人完成组织身份验证，管理员核对真实内部UserID | 成员有效，不能用昵称代替身份 |

后台标签和账号能力可能不同；入口不存在时先记录账号限制，不使用非官方个人号登录、Hook或绕过限制的方案。二维码、登录信息和密钥不要发到聊天或加入Git。

## 收不到时检查

1. 确认扫码绑定的是同一组织内的同一有效成员，而非另一个微信号或组织。
2. 检查应用可见范围、成员是否已停用、是否停用了该应用的消息接收。
3. 区分“会话里能看到消息”和“系统弹出提醒”；免打扰及手机通知设置可能影响提醒。
4. API code0只表示接口接受，不能代替手机收件。结果不明时不要盲目重发；先核对发送账本、回执和客户端。
