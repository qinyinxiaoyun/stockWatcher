# 独立订阅实施与 TrendRadar 借鉴计划

本阶段于2026-10-22获操作者授权实施。首版面向现有组织，沿用Python3.12、唯一worker和企业微信应用；本地实现与离线验收不自动新增生产成员或扩大真实投递范围。

## 本阶段顺序与验收

1. **成员与迁移**：增加组织/成员身份、角色、启停状态和独立订阅版本。新成员空订阅；通过显式迁移指定唯一旧配置拥有者，保留原股票、关注点、版本与已处理基线。存在未完成旧通知/意图任务时拒绝切换。旧全局模式继续兼容。
2. **配置与权限**：复用明确命令、确认和受约束自然语言操作；成员只能读写自己的配置。所有确认、上下文、审计、异步任务绑定成员；模型调用前后均验证成员资格和订阅版本，远程调用不持有写事务。
3. **共享内容与分析**：合并各成员有效检索需求，持久保存规范报道、修订及确切事件证据。按“事件/报道版本×目标×规范化关注配置×模型/提示词/结构版本”分析与缓存，相同公开需求复用，私有上下文隔离。schema4在质量筛选后按兼容范围组织最多5项小批请求，逐项校验与恢复，逻辑任务和token均有预算限制。
4. **成员评估与投递**：分析缓存、成员评估和成员/渠道投递各自去重。单目标分析避免跨公司套用方向；同成员同篇多项命中合并。入队原子或可恢复，失败只重试失败成员，发送每段前复查成员与订阅状态。新订阅从生效时间开始，普通配置变更不自动重发旧闻。
5. **集成验收**：补CLI成员准入、撤权、显式旧配置归属与成员配置入口；worker按持久模式标志选择兼容或独立订阅流程。完整离线覆盖共享抓取/分析、不同关注点、跨成员权限、版本冲突、撤权竞态、基线、失败与重启恢复。执行完整pytest及格式检查。

上述五项首版已实现，以下是2026-10-22的历史发布记录：生产代码0c988da…，操作者指定原拥有者MaTianye，沿用实际UserID `MaTianYe` 注册为唯一成员及admin，迁移原3只股票及配置、68条已处理记录和3个基线，当时配置版本为1。MONITOR_ENABLED=true沿用原授权状态，app/worker及公网健康检查通过；Windows离线368 passed/1 skipped，Linux CI369 passed。schema4质量策略及当前发布、验证状态以[PROGRESS.md](PROGRESS.md)为准，不将这次旧发布记录作为新策略已上线的证据。代码更新不自动新增成员、启用监控或发送测试消息。

## 运维与兼容入口

`init-db`升级至schema4但不改变原有运行模式。schema4保留既有配置、seen、评估、outbox及已接受分段，并从历史报道和通知补建规范身份/提醒证据，不清库、不全量重建首次基线。`members add USERID`仅准入空订阅，`members assign-legacy-owner USERID`才明确原拥有者并启用独立模式；要求组织身份已配置、拥有者先准入且个人配置为空、旧队列和运行中监控已排空。生产迁移先按现有流程备份，升级后不得直接运行低schema版本旧镜像。

`members list`查看准入/停用状态；`members revoke USERID`撤销资格；再次add恢复资格并从恢复时间监控。`members analysis USERID --private`将后续分析缓存按成员隔离，`--shared`允许相同公开关注需求在本组织内复用。改变资格/分析范围会递增资格代次，使旧异步任务和旧通知失效。

`config --member USERID`查询个人快照，`command "明确指令" --member USERID`在可信本地入口执行该成员自己的配置操作。成员模式下无成员的配置查询或未知用户命令会拒绝，不会落回全局配置。企业微信中已准入成员继续使用原有“帮助”“查看监控”、股票/方向/关注点/等级及确认命令，只影响本人。

手工历史补查在成员模式下必须增加`--member USERID`，保留原有唯一启用目标、1～24小时窗口、最多10个逻辑任务和真实写入确认约束；真实写入还须显式`--real --ack-max-notifications 10`。默认模拟及dry-run继续使用临时副本。成员模式`--dry-run --real`可抓取真实新闻，但DeepSeek只读取已有成功缓存，不新增模型调用，无缓存任务保持待处理。人工补查不受普通实时2小时窗口自动扩展或触发，也不扩大成员/收件范围；本地演示、离线测试与生产真实迁移分别验收。

## schema4新闻质量与提醒

规范报道使用来源身份、上游ID及规范URL别名，保留原始观察和不可覆盖的first_seen。摘要、空白、高亮、媒体/追踪参数等展示差异不单独产生实质修订；明确更正金额、撤销、取消、计划转实施等新证据可重新评估。跨URL采用保守确切事件去重，主体、类型、日期及规范事实标题等一致才复用；未知事件仍按报道区分，不凭相似标题合并不同事件。同成员后补关联目标可补齐未发送材料，不能另发已通知原文。

新闻模型之前过滤高置信纯行情模板：资金净买卖、融资融券日报、涨跌成交回顾、技术指标和普通目标价观点。混有业绩、订单、产品商业化、供需价格、监管、重大减持、回购或经营风险新事实的文章继续判断；“卖出”“下跌”不是黑名单，规则不确定时保留待判断。

普通实时事实固定在可信披露后2小时到期；来源未知、冲突或未来超过5分钟时待核对，不能以首次抓取或页面刷新重置寿命。隔夜经营事实在09:00至09:15收集分析，09:10至09:15前最多一次晨间摘要、最多3个独立事件；没有已完成有效事件就不发，超容量不变成日内逐条补发。疑似重大风险具备明确披露证据时可使用来源时间起24小时例外，模型判重大本身不能突破时效。

普通重要事件按成员在半小时边界合并，每30分钟最多一条摘要、每条最多3个独立事件；其余候选继续排队，到期退出且不续期。重大事件及时入队，仍保留固定有效期。发送每段前复查成员资格、订阅及到期时间，保留已接受分段检查点；未知网络结果可能重复的限制仍然存在。

## AI调用、缓存及预算约定

- 分析任务以事件/报道版本和实际目标/关注需求为单位，同公开目标同关注需求复用；不同目标分别返回影响。收件人、阈值、渠道由本地规则处理，成员配置版本用于网络前后一致性校验，模型/提示词/结构版本参与缓存。
- 质量过滤、去重及缓存之后，DeepSeek每批最多5个独立task_id，仅合并同组织和兼容隐私域；私有成员独立，重大预留任务与普通任务分批。每项单独返回重要性、方向、依据、新事实和待核实事项；无证据允许不确定，关注点不屏蔽其他重大风险。
- 每轮最多10个新逻辑任务，另计实际HTTP请求、失败及缓存命中；成员模式禁用模型内部隐含重试。JSON损坏或任务身份缺失/重复/未知时不能猜测成功；身份完整时逐项校验，成功结果持久复用，仅失败项进入恢复。
- 持久失败状态与成功缓存分离，同公共键同轮只尝试一次。首次、第二次失败分别冷却5、15分钟，第三次及以后冷却60分钟；尚有时效的任务才恢复，疑似重大任务也不无限重试。预算不足保持待处理，不写普通/已完成。提供方熔断、缓存与失败恢复按组织及私有域隔离，持久成员游标轮转。
- 新闻默认每小时60,000、北京时间自然日300,000 token，20%保留给疑似重大任务。环境变量 `NEWS_HOURLY_TOKEN_BUDGET`、`NEWS_DAILY_TOKEN_BUDGET`、`NEWS_MAJOR_RESERVE_FRACTION`可调整，网络前短事务原子预留，网络后结算；遗留超时预留由worker启动保守恢复。
- 真实usage保存输入、输出、缓存命中/未命中、总token与模型指纹等安全元数据；已取得usage的截断和结构失败同样记录。缺失usage保持实际token未知，保守估算单列预算收费，不冒充实耗，不记录模型原文/提示词/凭证。管理意图按intent独立统计，不计入新闻预算；token不等于供应商费用账单。
- 真实东方财富平时使用主检索词，每15分钟（:00/:15/:30/:45）补查全部别名/主题关键词，主词结果为空或失败立即回退完整查询；主词非空仍须定期补查，不能据此认定覆盖完整。主题关键词保持这一覆盖规则，不修改成员配置。
- 文章池、分析缓存及成员评估通常保留15天，事件与成员提醒证据至少保留30天；outbox继续保留幂等及投递记录。24小时发现窗口不等于实时推送有效期。成功缓存预览不会为真实DeepSeek dry-run新增调用。

抓取和模型请求继续顺序执行，唯一worker承担后台入口。合成回放用于验证规则、身份、失败恢复和通知幂等；真实模型召回与token节省须另做受控对照，不宣称已经达到50%节省目标或供应商费用精确核算。

## TrendRadar的可取之处及安排

调研源码基线为[sansan0/TrendRadar 68c8916c](https://github.com/sansan0/TrendRadar/tree/68c8916c450f8c8dd36cb88a189f7c2e46681ab5)。借鉴架构思路，自行实现本项目需求。

| 做法 | 安排 |
| --- | --- |
| 统一来源结构、采集与筛选分离 | 本阶段先落地来源身份、文章版本、共享文章池；后续增加完整来源适配接口与独立游标 |
| 持久采集历史，避免只保留本轮结果 | 本阶段保存文章与分析缓存；后续补覆盖率、游标完整性和来源健康指标 |
| AI按兴趣分类、缓存与配置变化更新 | 本阶段按目标/关注组复用，使用明确版本化缓存规则；保留本项目严格结果校验 |
| 采集、分析、推送分别按时段控制 | schema4已加入普通实时、隔夜晨间及重大例外窗口；盘后汇总等后续安排仍使用唯一worker，不移植额外cron |
| 多渠道格式适配与分段 | 本阶段保留持久outbox及分段检查点，增加成员隔离；其他渠道后续按需要接入 |
| 排名历史、出现频次、舆情简报 | 后续作为辅助视角，不以热度替代证券重要性或原始披露证据 |

TrendRadar主链路没有替本项目解决多成员独立订阅；其热榜依赖NewsNow、AI简报主要使用标题。新来源按原规划优先公告/IR等许可清楚的数据，NewsNow/RSS保留为后续逐源候选，本阶段不调用或启用新增来源。
