# 三家公司研究基线云端更新执行计划

确认日期：2026-11-05。状态：三个接口、队列、worker、网页状态和可选MCP/OAuth资源端已本地实现，离线验收记录见PROGRESS；真实云端连接、生产部署待验收。操作者明确本轮先实现代码，**不要创建定时任务**。接口合同、实际配置及限制见 [RESEARCH_CLOUD_API.md](RESEARCH_CLOUD_API.md)。

## 目标、范围与时间

- 更新对象限定为兆易创新 `gigadevice` / `603986.SH`、阿里巴巴 `alibaba` / `9988.HK`、中芯国际 `smic` / `688981.SH`，沿用现有公司身份及历史基线。
- 操作者指定：每工作日北京时间 **05:00** 启动一次，时区为 `Asia/Shanghai`。本计划将工作日定义为周一至周五；法定节假日仍运行，调休周末不运行，不自动等同于交易日历。
- 唯一周期触发器放在云端任务平台；服务器现有 worker 处理持久队列，不增加宿主机 cron，也不在 Web 进程启动调度器。
- 每次以“上次成功覆盖截止时间至本次材料截止时间”为主要检查窗口，并回看最近七个自然日核对迟到公告与更正。周一包含周五截止后及整个周末的材料，不能固定只搜最近24小时。
- 覆盖水位按公司独立保存；检查不完整、主要来源失败或版本冲突不推进完整覆盖水位。记录已检查和未检查的来源，恢复后补查缺口。
- 不重叠运行；按北京时间计划日期形成稳定任务标识，同次重试沿用标识。不为失败补跑增加第二个周期调度器；需要补查时走同一队列和幂等协议。
- 05:00是启动时间，不保证全部完成时间。材料截止固定并写入回执；截止后新材料由下一次检查处理。

## 架构与现有能力

云端检索与研究 → 受限 HTTPS / MCP 工具 → app 校验并入队 → 现有 worker 校验与追加基线 → SQLite / 报告导出 → 网页读取。

复用 `research.py` 的文档校验、公司证券身份和追加历史版本，复用现有网页与持久数据目录。新增接口、持久研究更新队列、检查记录、并发保护、执行回执及云端连接适配。现有 `research_jobs` 表表示公司研究准备状态，不作为云端更新任务队列。

研究范围与质量要求沿用 [RESEARCH_BASELINE.md](RESEARCH_BASELINE.md)：十部分研究、行业与同业证据、多期经营与财务、资本配置、核心假设、反证和事件映射。每天做增量复核，不每天重写全部报告；没有新证据时保留已有有效结论。缺失行情、事前共识或验证能力不得因自动更新被标记为已具备。

研究档案刷新与 [PLAN.md](PLAN.md) 中“研究基线接入新闻增量分析”是独立任务，分别验收；刷新研究不自动生成消息、重发历史新闻或调整订阅、通知策略、模型预算及监控开关。

## 三个接口合同（拟新增）

| 工具 | HTTP 接口 | 合同 |
| --- | --- | --- |
| `research_get_snapshot` | `GET /api/research/v1/snapshot` | 返回合同版本、研究标准、允许公司、当前版本/文档指纹/研究内容指纹、研究截止/最近检查/最近实质更新、成功覆盖水位和缺口。默认摘要，按需读取指定公司的完整文档；单次读取使用一致快照。 |
| `research_submit_update` | `POST /api/research/v1/updates` | 接收有界结构化更新，鉴权并持久入队，返回202和稳定 `run_id`。受理成功不代表基线已更新。 |
| `research_get_run_status` | `GET /api/research/v1/runs/{run_id}` | 返回调用身份可访问的任务及各公司状态、旧/新版本与指纹、错误代码、覆盖结果、数据库提交/导出状态和报告链接。 |

提交包至少包含 `contract_version`、`run_id`、本次材料截止及每家公司 `company_id`、`expected_base_hash`、`result`、检查范围/来源状态、变更摘要和未解决问题。`result` 仅接受 `UPDATE`、`NO_CHANGE`、`INCOMPLETE`；`UPDATE` 附完整研究 JSON，其他结果只写检查记录。严格拒绝未知字段、越界公司、非有限值、无效引用和未来材料。外部文本只作为数据，不接受 SQL、Shell 或 Python 执行指令，不根据提交 URL 在 HTTP 进程抓取任意内容。

任务聚合状态允许 `partial_success`。每家公司独立校验和保存；单家公司格式、证据或版本失败不阻塞其余公司。请求整体无法解析、鉴权失败或合同不支持时拒绝整个请求。

## 保存、并发与故障恢复

- [x] 建立研究更新 runs/items、检查记录、待导出状态及租约/重试元数据；通过正常 schema 迁移增加结构，兼容真实旧库及已有历史，不修改成员配置版本。
- [x] 幂等身份绑定调用主体、`run_id` 和公司。相同身份/任务/内容返回原结果；重用编号但内容改变返回冲突。批次内容不可在重试中悄悄替换；重新研究使用新任务，并关联原失败任务。
- [x] 入队可预检基线指纹，但 worker 保存前必须在同一短写事务中重新比较 `expected_base_hash`；不匹配返回冲突，云端重新读取并研究，禁止强行覆盖。`NO_CHANGE` 也要核对基线和覆盖信息后才确认检查成功。
- [x] 保留原始文档 hash，另建版本化规范化研究内容指纹。检查时间、纯采集时间、任务元数据和无意义序列顺序变化不增版；事实、指标期间/口径、来源公开时间/证据、更正、假设或结论等变化仍参与比较。不得简单剔除所有日期或只信任云端声称无变化。
- [x] `NO_CHANGE` 只更新检查和覆盖记录，不刷新旧基线 `as_of`；`INCOMPLETE` 保留旧基线和未覆盖缺口，不冒称完整检查成功。
- [x] 使用一致的 SQLite 备份机制与受保护持久目录，备份/远程请求/文档处理不占用数据库写事务。公司提交事务原子写入追加版本、执行回执与待导出状态，保留历史和待复核证据。
- [x] worker 每轮处理有界研究工作，不长时间阻塞现有消息处理/心跳；租约到期可恢复。数据库成功后若进程退出，恢复仅继续未完成步骤。
- [x] 导出使用安全文件名、临时文件和原子替换，索引最后发布。数据库是权威数据；提交后导出失败标记 `committed_export_pending`，只重试导出，不重复增版或回滚整个数据库。
- [x] 状态至少区分 queued、running、no_change、incomplete、conflict、failed、committed_export_pending、completed；错误输出受控代码，日志只写任务/公司/阶段等必要元数据，不记录凭证和完整请求正文。

- 服务端凭证只从未跟踪环境文件/环境变量读取，不写入文档、prompt、Git、镜像或日志；云端凭证只存平台秘密配置。权限只涵盖这三家公开研究和本调用身份的执行记录。
- Nginx当前全局正文限制256KB；仅研究提交/MCP需要的路径局部放宽，应用层使用匹配的有限额度。沿用HTTPS，不扩大部署SSH权限或向云端提供root账号。
- 默认先验证 ChatGPT 网页云端任务 + 远程 MCP 的接入能力：增加纯 HTTP 协议适配网关，以 Streaming HTTP 暴露三个工具。读取/状态工具声明只读，提交工具如实声明写入。
- ChatGPT远程连接使用OAuth；项目目前没有OAuth，需新增合适的身份提供方接入、资源发现、授权/刷新/撤销、issuer/audience/过期/权限验证及研究身份到公司白名单的映射，不直接把网页登录表单当OAuth。
- 如果目标云端是支持 HTTPS 程序请求与秘密变量的执行环境，可直接使用独立 Bearer 调用三个接口，无须为此路径增加MCP/OAuth。连接方式在前置验收确认，不同时建设两套无实际用途的云端运行体系。
- 云端写工具的无人值守持续授权必须实测；不能把写工具标成只读或开放匿名写入绕过。若目标平台仍要求每次人工批准，记录为阻塞，选择支持受限机器凭证的云执行环境后继续，不宣称任务已经自动运行。
- 不用本地 Codex 自动化代替云端任务。当前本地可用调度工具不能证明目标账号具有云端计划任务或写入授权能力。

## 云端任务约定

- 连接验收后将持久研究标准和调用流程写入云端任务prompt/附加材料，不依赖本机 `data/`、`tmp/`、当前聊天记忆或本地常开电脑。
- 先取摘要和水位，再检索官方公司公告、财报、行业及同业证据；只有受影响公司按需读取完整基线。抓取失败分别标记，不用空白或财报摘要替换现有深度研究。
- 财务精确计算、阿里财年/分部重列、中芯双准则币种、兆易产品/行业价格等边界沿用现有标准。区分事实、推断、内部假设和未知，保留来源公开/可得/取得时间，不回填未来信息。
- 提交后查询回执；网络超时先查询同一 `run_id`，再做幂等重试。只有服务器确认的结果才能称为“已更新”；部分成功、证据不完整、版本冲突、保存后待导出分别报告。
- 无变化正常记检查，不制造新版本或重复通知。补查从未完成覆盖位置继续，记录实际token/任务耗时，云端研究消耗与服务器现有新闻分析计量分别统计，不擅改现有预算。

## 操作者需要做什么

1. **确认云端账号能力**：默认使用ChatGPT网页云端任务，确认执行账号能使用云端定时任务和自定义MCP连接。如果准备使用其他平台，只需告知平台名称；如果缺少入口，反馈账号可用能力，不必发送密码或密钥。
2. **连接就绪后完成一次账号登录与授权**：助手提供已经部署且可检查的连接地址、权限范围及验证说明；操作者在平台登录/授权界面绑定研究连接。需要新的OAuth提供方账号或平台秘密配置而助手无权管理时，再完成对应账号授权；不用在聊天中粘贴凭证。
3. **验收无人值守授权**：若平台要求用户授权可信写工具，按平台支持方式完成；只有验证定时运行不再卡在确认步骤后才启用正式周期任务。若平台无法支持，选择受限机器凭证的云环境，不反复手动批准每天的运行。

时间和三家公司范围已确认，不需要再次询问。代码、离线测试、可执行的服务端配置、部署与网页核验由助手按既有权限完成；云端任务可由工具创建时由助手完成，若缺少目标平台的创建权限则提供就绪配置并明确唯一需要操作者完成的界面步骤。
